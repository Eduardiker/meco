Catálogo Oficial de Plugins (14 Módulos)

Extensiones 100% desacopladas del Core bajo el estándar oficial de 2 bloques (calls.py ➔ actions.py). Cada plugin opera con un MecoContext aislado sujeto a la Autoridad de Permisos.

Diferenciación Clave: Módulos Nativos del Sistema vs Plugins Desacoplados

🏛️ Módulos Nativos (Nivel 2: modules/)

Son componentes estructurales internos integrados en el Microkernel Core. No son plugins. Proveen servicios esenciales del sistema:

  • PAM (modules/pam/): "Pregúntale a Meco". Adapta las respuestas al usuario con 4 perfiles de estilo y gestiona la interacción.
  • CAM (modules/cam/): "Conecta a Meco". Gobierna la salida a Internet (políticas de dominios, disyuntores, modo offline) y gestiona el Bus IPC inter-plugins con prioridades P1-P3.

🧩 Plugins Desacoplados (Nivel 3: meco-hub)

Son extensiones y aplicaciones funcionales 100% externas al código fuente del Core.

  • Siguen el estándar de 2 bloques: calls.py (comandos) ➔ actions.py (lógica).
  • Se aíslan en memoria bajo MecoContext con disyuntores individuales.
  • Dependen de los Módulos Nativos para interactuar con humanos o salir a la red.
⚡ ¿Cómo dependen los Plugins de los Módulos? Si un plugin desea hablar con el usuario con tono adaptado, depende de PAM (permiso pam:interact). Si necesita hacer peticiones a Internet, depende de CAM Network (permiso cam:internet). Si necesita avisar a otros plugins de un evento crítico, depende de CAM IPC Bus (permiso cam:ipc).

Guía Técnica: Creación de Módulos del Sistema

Documentación técnica para desarrolladores de meco-core. Comprende la arquitectura interna, las reglas de diseño para extender el Nivel 2 y la diferencia estricta entre un Módulo del Sistema y un Plugin desacoplado.

Diferenciación Fundamental de Arquitectura (Nivel 2 vs Nivel 3)

En M.E.C.O., un Módulo NO es un Plugin. Confundir ambos conceptos rompe la soberanía y el desacoplamiento del Microkernel.

Criterio Técnico Módulo Nativo (Nivel 2: modules/) Plugin Desacoplado (Nivel 3: meco-hub)
Ubicación en Git Vive dentro de Eduardiker/meco-core (directorio modules/) Vive en el registro desacoplado Eduardiker/meco-hub
Espacio de Proceso Mismo proceso e hilo principal del Microkernel (acceso directo a kernel) Aislado bajo MecoContext sujeto a ACL y permisos criptográficos
Responsabilidad Servicios estructurales de sistema (PAM: Adaptación/Interacción; CAM: Red/IPC) Aplicaciones y casos de uso finales (Telegram, Domótica, Backups, IA)
Ciclo de Vida Arranque síncrono durante el _bootstrap_modules() del Microkernel Descubrimiento dinámico, supervisión continua y recarga en caliente
Tolerancia a Fallos Crítico: si un módulo falla, degrada una capacidad central del sistema No-crítico: protegido por Circuit Breakers (5 fallos en 60s lo aíslan)
Estándar de Archivos Paquete Python nativo: __init__.py + subsistemas (ej. adapter.py, network.py) Estándar estricto de 2 bloques: calls.py ➔ actions.py + manifest.json

Regla de Oro: ¿Tu código añade una funcionalidad de usuario (ej. consultar el tiempo, avisar por Telegram, encender luces)? ➔ Crea un Plugin en meco-hub. ¿Tu código provee un servicio transversal del que dependerán los demás plugins (ej. un nuevo bus criptográfico, un motor de auditoría central, un gestor de energía hardware)? ➔ Crea un Módulo en meco-core.

Contrato de Ciclo de Vida de un Módulo del Sistema

Todo módulo en modules/ debe cumplir con el contrato de orquestación del microkernel. No debe bloquear el arranque del sistema ni realizar llamadas de red síncronas en su constructor.

1

initialize(kernel)

Se invoca tras instanciar la clase. Recibe la referencia MecoMicrokernel. El módulo enlaza aquí la Autoridad de Permisos, el bus CAM y el adaptador PAM sin abrir sockets externos.

2

start()

Puesta en marcha activa. Levanta hilos de escucha, registra observadores en el Bus IPC de CAM y activa tareas programadas. Debe ser no-bloqueante.

3

status() -> dict

Devuelve un diccionario atómico con la telemetría del módulo. Este diccionario es consumido por el Modo Esquemático del Core (Nivel 1) y por PAM para reportes al usuario.

4

shutdown()

Parada ordenada ante señales SIGTERM/SIGINT. Cierra sockets, vuelca buffers a disco y desvincula listeners del bus para evitar fugas de memoria o file descriptors.

Paso a Paso: Integración de un Módulo en meco-core

Ejemplo práctico: Creación del módulo nativo hipotético modules/sam/ (Sistema de Auditoría y Métricas).

Paso 1: Crear la estructura del directorio

Crea una nueva carpeta bajo modules/ con su archivo de inicialización: 

mkdir -p modules/sam
touch modules/sam/__init__.py modules/sam/audit_engine.py

Paso 2: Registrar el módulo en core/kernel.py

En el método _bootstrap_modules() de core/kernel.py, instancia el nuevo módulo y vincúlalo al Microkernel: 

from modules.sam import SecurityAuditManager

# Dentro de MecoMicrokernel.__init__:
self.sam = SecurityAuditManager(kernel=self)
self.sam.initialize()

Paso 3: Definir el permiso de acceso en core/permissions.py

Declara el nuevo ámbito de permisos para que los plugins que deseen usar este módulo deban solicitarlo explícitamente: 

# En VALID_PERMISSIONS de core/permissions.py:
"sam:audit",  # Permiso para consultar o emitir registros al módulo SAM

Plantilla Boilerplate de un Módulo Nativo (modules/sam/__init__.py)

Estructura base recomendada lista para implementar en modules/<nombre>/__init__.py: 

#!/usr/bin/env python3
"""
M.E.C.O. - Nivel 2: Módulo Nativo del Sistema (modules/sam/__init__.py)
Plantilla oficial de módulo estructural de Nivel 2.
"""
import time
import logging

class SystemAuditModule:
    """
    Módulo SAM (Security & Audit Manager) - Nivel 2 de M.E.C.O.
    Provee servicios transversales de auditoría para el Core y los Plugins.
    """

    def __init__(self, kernel=None, enabled: bool = True):
        self.kernel = kernel
        self.enabled = bool(enabled)
        self.started_at = None
        self.events_audited = 0
        self.logger = logging.getLogger("meco.modules.sam")

    def initialize(self, kernel=None):
        """Inicializa dependencias con el Microkernel sin bloquear el arranque."""
        if kernel:
            self.kernel = kernel
        self.logger.info("[SAM:READY] Módulo de Auditoría inicializado.")

    def start(self):
        """Puesta en marcha activa: suscripción al Bus IPC de CAM (Nivel 2)."""
        self.started_at = time.time()
        if self.kernel and hasattr(self.kernel, "cam") and self.kernel.cam:
            # Suscribirse a eventos de prioridad 1 (Críticos)
            self.kernel.cam.ipc.subscribe("audit:*", self.handle_audit_event, priority=1)
        self.logger.info("[SAM:STARTED] Escucha de eventos activa.")

        """Procesa y sella criptográficamente eventos del sistema."""
        self.events_audited += 1
        # Lógica interna del módulo...

    def status(self) -> dict:
        """Telemetría estructurada consumida por el Modo Esquemático (Core) y PAM."""
        return {
            "module": "sam",
            "tier": 2,
            "status": "nominal" if self.enabled else "disabled",
            "events_audited": self.events_audited,

Diseño Militar y Táctico

Pilares de Autopreservación

M.E.C.O. no asume un entorno ideal. Está diseñado para sobrevivir a caídas de red, ataques de ransomware en SMB, agotamiento de memoria y fallos en cascada.

🔒

Instancia Única & Autovacuna RAM

Bloqueo por socket exclusivo en 127.0.0.1:48899 para evitar instancias zombies. Recolección de basura periódica con libc.malloc_trim(0) manteniendo el consumo RSS estabilizado entre 45 MB y 65 MB.

⚡

Circuit Breakers por Plugin

Si una API externa o base de datos falla 5 veces consecutivas en 60 segundos, su disyuntor se abre (CIRCUIT_OPEN), aislando el fallo y evitando que bloquee el microkernel o los hilos de interacción.

🛡

Escudo Canario inotify & FIM

Trampas canario en carpetas compartidas SMB monitorizadas mediante inotify a nivel de kernel. Si un ransomware toca el fichero canario, el sistema activa el Modo Búnker en menos de 50 milisegundos cortando accesos.

📡

Malla UDP Táctica Fuera de Banda

Ante la caída total de la fibra óptica o pérdida de pasarelas en la nube, el plugin de supervivencia P2P despierta un socket UDP táctico con balizas cifradas HMAC sin consumir ciclos de CPU en reposo.

Despliegue Rápido de M.E.C.O.

Instala el microkernel soberano en cualquier servidor o Mini-PC con Linux (Ubuntu, Debian, Alpine) y Python 3.10+. 

# 1. Clonar el repositorio del Microkernel Core
git clone https://github.com/Eduardiker/meco-core.git meco
cd meco

# 2. Configurar perfil de inicio
cp config/meco.example.yaml config/meco.yaml

# 3. Consultar estado en Modo Conversacional (vía PAM)
python3 meco.py --cmd "/estado"

# 4. Modo Esquemático Básico del Core (Rescate Nivel 1)
python3 meco.py --schematic --cmd "status"

# 5. Sincronizar catálogo oficial desde meco-hub
python3 meco.py --sync-hub ../meco-hub --cmd "/ayuda"

# 6. Arrancar como servicio / daemon continuo
python3 meco.py --daemon
# Guardar en /etc/systemd/system/meco.service
[Unit]
Description=M.E.C.O. Autonomous Sovereign Microkernel
After=network.target docker.service

[Service]
Type=simple
User=irt
WorkingDirectory=/opt/meco
ExecStart=/usr/bin/python3 /opt/meco/meco.py --daemon
Restart=always
RestartSec=5
MemoryMax=250M

[Install]
WantedBy=multi-user.target
