Nivel 2: Módulos Nativos de meco-core

Módulos del Sistema (Nivel 2)

Componentes estructurales internos de meco-core con nombres e identificadores exactos. A diferencia de los plugins externos, los módulos residen en el repositorio del Core, proporcionan los servicios fundamentales de gobernanza y sirven de puente vital para las extensiones.

PAM

Pregúntale a Meco

modules/pam/ · Adaptación e Interacción con el Usuario

Nativo Core

Motor de humanización e interfaz interactiva del sistema. Centraliza la entrada de comandos y adapta las respuestas dinámicamente mediante ResponseAdapter en 4 perfiles en caliente (Conversacional, Conciso, Técnico y Esquemático), asegurando que el usuario o las interfaces cliente reciban la información en el tono adecuado.

Componentes: ResponseAdapter (engine.py), Router (cli.py)
Perfiles: Conversacional, Conciso, Técnico, Esquemático
Permiso Requerido: pam:interact
● Integrado y Activo modules/pam/engine.py
CAM

Conecta a Meco

modules/cam/ · Conectividad a Internet e IPC Inter-Plugins

Nativo Core

Gobernador soberano de todas las comunicaciones de red externa y del bus interno entre plugins. Implementa listas blancas de dominios HTTP, disyuntores de red ante corte de fibra óptica y el bus IPC asíncrono inter-plugins con 3 niveles de prioridad estricta (P1 Crítica, P2 Interactiva, P3 Fondo).

Componentes: NetManager (net.py), InterPluginBus (ipc.py)
Prioridades IPC: P1 (Crítica) · P2 (Interactiva) · P3 (Background)
Permisos Requeridos: cam:internet, cam:ipc
● Integrado y Activo modules/cam/net.py + ipc.py
SAM

Seguridad y Auditoría Meco

modules/sam/ · Gobernanza y Permisos Criptográficos

Nativo Core

Módulo de gobernanza criptográfica y control de accesos. Gestiona la matriz estricta de permisos de plugins, valida firmas SHA-256 de los manifiestos oficiales, audita llamadas a subprocesos del sistema operativo y coordina el aislamiento preventivo y modo búnker ante manipulaciones no autorizadas.

Componentes: PermissionAuthority, AuditLogger, SHA-256 Verifier
Filosofía: Strict Deny por Defecto & Auditoría Criptográfica
Ámbitos Clave: core:admin, system:exec
● Módulo Estructural N2 modules/sam/governance.py
MAM

Memoria y Almacenamiento Meco

modules/mam/ · Persistencia y Gobernanza de Recursos

Nativo Core

Gobernador de ciclo de vida del almacenamiento persistente, estados de plugins y consumo de memoria RAM. Ejecuta recolección forzada con glibc malloc_trim(0) para mitigar la fragmentación de memoria en Linux de bajo consumo y salvaguarda las bases de datos SQLite locales y el histórico.

Componentes: StorageGovernor, MemoryTrimmer (malloc_trim), StateVault
Consumo RSS: Mantiene MECO en 45 MB – 65 MB estables
Permiso Requerido: core:storage
● Módulo Estructural N2 modules/mam/storage.py
VAM

Vigía Autónomo Meco

modules/vam/ · Watchdog y Supervivencia del Sistema

Nativo Core

Centinela de disponibilidad y watchdog de bajo nivel del Microkernel. Monitorea los bucles de eventos, supervisa el estado de salud de cada plugin desacoplado, gestiona el estado de los Circuit Breakers (Closed/Open/Half-Open) y orquesta la activación del modo supervivencia fuera de banda si falla la conectividad.

Componentes: WatchdogDaemon, CircuitBreakerRegistry, FailoverEngine
Tolerancia a Fallos: Aislamiento de caídas individuales (0 downtime global)
Supervivencia: Activación automática de contingencias
● Módulo Estructural N2 modules/vam/watchdog.py

Nivel 3: Meco-Hub

Catálogo Oficial de Plugins (14 Extensiones Desacopladas de meco-hub)

Extensiones 100% desacopladas del Core bajo el estándar oficial de 2 bloques (calls.py ➔ actions.py). Cada plugin opera con un MecoContext aislado sujeto a la Autoridad de Permisos.

Diferenciación Clave: Módulos Nativos del Sistema vs Plugins Desacoplados

🏛️ Módulos Nativos (Nivel 2: modules/)

Son componentes estructurales internos integrados en el Microkernel Core. No son plugins. Proveen servicios esenciales del sistema:

  • PAM (modules/pam/): "Pregúntale a Meco". Adapta las respuestas al usuario con 4 perfiles de estilo y gestiona la interacción.
  • CAM (modules/cam/): "Conecta a Meco". Gobierna la salida a Internet (políticas de dominios, disyuntores, modo offline) y gestiona el Bus IPC inter-plugins con prioridades P1-P3.

🧩 Plugins Desacoplados (Nivel 3: meco-hub)

Son extensiones y aplicaciones funcionales 100% externas al código fuente del Core.

  • Siguen el estándar de 2 bloques: calls.py (comandos) ➔ actions.py (lógica).
  • Se aíslan en memoria bajo MecoContext con disyuntores individuales.
  • Dependen de los Módulos Nativos para interactuar con humanos o salir a la red.
⚡ ¿Cómo dependen los Plugins de los Módulos? Si un plugin desea hablar con el usuario con tono adaptado, depende de PAM (permiso pam:interact). Si necesita hacer peticiones a Internet, depende de CAM Network (permiso cam:internet). Si necesita avisar a otros plugins de un evento crítico, depende de CAM IPC Bus (permiso cam:ipc).

Diseño Militar y Táctico

Pilares de Autopreservación

M.E.C.O. no asume un entorno ideal. Está diseñado para sobrevivir a caídas de red, ataques de ransomware en SMB, agotamiento de memoria y fallos en cascada.

🔒

Instancia Única & Autovacuna RAM

Bloqueo por socket exclusivo en 127.0.0.1:48899 para evitar instancias zombies. Recolección de basura periódica con libc.malloc_trim(0) manteniendo el consumo RSS estabilizado entre 45 MB y 65 MB.

⚡

Circuit Breakers por Plugin

Si una API externa o base de datos falla 5 veces consecutivas en 60 segundos, su disyuntor se abre (CIRCUIT_OPEN), aislando el fallo y evitando que bloquee el microkernel o los hilos de interacción.

🛡

Escudo Canario inotify & FIM

Trampas canario en carpetas compartidas SMB monitorizadas mediante inotify a nivel de kernel. Si un ransomware toca el fichero canario, el sistema activa el Modo Búnker en menos de 50 milisegundos cortando accesos.

📡

Malla UDP Táctica Fuera de Banda

Ante la caída total de la fibra óptica o pérdida de pasarelas en la nube, el plugin de supervivencia P2P despierta un socket UDP táctico con balizas cifradas HMAC sin consumir ciclos de CPU en reposo.

Despliegue Rápido de M.E.C.O.

Instala el microkernel soberano en cualquier servidor o Mini-PC con Linux (Ubuntu, Debian, Alpine) y Python 3.10+. 

# 1. Clonar el repositorio del Microkernel Core
git clone https://github.com/Eduardiker/meco-core.git meco
cd meco

# 2. Configurar perfil de inicio
cp config/meco.example.yaml config/meco.yaml

# 3. Consultar estado en Modo Conversacional (vía PAM)
python3 meco.py --cmd "/estado"

# 4. Modo Esquemático Básico del Core (Rescate Nivel 1)
python3 meco.py --schematic --cmd "status"

# 5. Sincronizar catálogo oficial desde meco-hub
python3 meco.py --sync-hub ../meco-hub --cmd "/ayuda"

# 6. Arrancar como servicio / daemon continuo
python3 meco.py --daemon
# Guardar en /etc/systemd/system/meco.service
[Unit]
Description=M.E.C.O. Autonomous Sovereign Microkernel
After=network.target docker.service

[Service]
Type=simple
User=irt
WorkingDirectory=/opt/meco
ExecStart=/usr/bin/python3 /opt/meco/meco.py --daemon
Restart=always
RestartSec=5
MemoryMax=250M

[Install]
WantedBy=multi-user.target
# config/meco.yaml — Arquitectura de 3 Niveles
admin:
  name: "Iker"
  allowed_telegram_ids: [123456789]
  language: "es"

core:
  schematic_mode: false
  permissions:
    default_policy: "strict"

modules:
  pam:
    default_style: "conversational" # conversational | concise | technical | schematic
  cam:
    offline_mode: false
    default_timeout_s: 10.0

plugins:
  hub_repo: "Eduardiker/meco-hub"
